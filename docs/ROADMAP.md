# COC War Tool 开发计划（ROADMAP）

> 本文件收录**暂缓开发**的方向（用户裁决：BCD 层先保存为计划，后续再开发）。
> 已列入计划的条目不代表已承诺实现；启动某项前应先在 RULES.md 对齐口径。

## B. 数据层

| # | 方向 | 动机 | 依赖/备注 | 优先级 |
|---|------|------|-----------|--------|
| B1 | 导入容错与 diff 预览 | 缺 `attack_order` 等不规范 JSON 会静默折叠记录（见 RULES §5）；导入前预览新增/变更成员，降低误导入 | 需要解析层规范化 order（order≤0 按序重编号） | 中 |
| B2 | CSV/Excel 导入导出 + 月度报告 | 表格化维护战报是常见需求；月度成绩单方便分享 | 可复用现有导出 JSON 逻辑；报告可并入 C1 | 中 |
| B3 | WebDAV 从备份升级为真同步 | 现为单向覆盖式备份，多设备各改各的会互相覆盖 | 版本化/冲突提示；需评估服务端能力 | 低 |

## C. 产品层

| # | 方向 | 动机 | 依赖/备注 | 优先级 |
|---|------|------|-----------|--------|
| C1 | 联赛赛季视图 | 每轮是独立事件，缺整个 CWL 赛季聚合视角：7 轮总览、出战轮换计划（联赛每人限打 1 次，排表是刚需）、进攻分配建议 | **与本次列表分组（EventListScreen 联赛分组 + SAABBCC C1C2 编码）天然衔接** | 高 |
| C2 | 开战预警与补刀建议 | 未进攻公示已有，可扩展开战提醒通知、基于剩余星数的补刀目标建议 | 需通知权限（已有基础） | 中 |
| C3 | 成员长期画像 | 参战率/三星率/活跃度趋势、连续未参战流失预警 | 依赖 stats 模块扩展 | 中 |
| C4 | 轻量 OCR 截屏结构化 | v3.0 删除了 AI 识别；现方案为截屏+手动浏览图库，未闭环 | ML Kit 离线 OCR，无云成本 | 中 |

## D. 工程层

| # | 方向 | 动机 | 依赖/备注 | 优先级 |
|---|------|------|-----------|--------|
| D1 | StatsCalculator 单元测试 | 核心统计零测试，口径反复横跳（满星率 v3.4→v3.5→现版）教训 | 纯函数可直接 JUnit 测；需先搭测试目录与依赖 | 高 |
| D2 | 引入 DI（Hilt/Koin） | 手写 `warViewModel` 在小规模可行，随模块化/测试推进吃力 | 涉及全局重构，风险中 | 低 |
| D3 | Compose UI 冒烟测试 | 防迁移/快照类回归（v3.9 教训） | 依赖 D1 的测试基建 | 低 |

## 建议推进顺序

1. **D1**（测试基建，成本低、立即护住统计口径）——**✅ 已落地**（见下）
2. **C1**（联赛赛季视图，与本次 C1C2 编码/分组改动衔接最顺）——**✅ 已落地**（见下）
3. **B1 → B2**（数据层容错与表格化，按需）
4. 其余（B3/C2/C3/C4/D2/D3）按用户需求与精力投入

## 与本次改动的关系

- 已落地：
  - 满星率口径（人数×3）、联赛 SAABBCC C1C2 编码（C1 场次归属 0/1 + C2 轮次）、
    联赛列表分组与「月初场/月中场」文案、refresh 竞态修复、详情页轮次字段修复、
    工具页「数据迁移修复」（旧联赛名称重编码 + 迁移前自动备份）；
  - **D1**：StatsCalculator 单元测试（`COCtools/src/test/.../StatsCalculatorTest.kt`，
    11 用例，覆盖满星率/三星率/进攻率/积分制/月度统计/未进攻排行；`testDebugUnitTest` 可运行）；
  - **C1**：联赛赛季视图（`domain/LeagueSeason.kt` 纯函数聚合 +
    `ui/season/LeagueSeasonScreen`，事件列表联赛分组组头点击进入，展示 7 轮总览与出战轮换）。
- C1 后续可扩展：出战轮换计划（排表）、每轮进攻分配建议（利用 `attackedRounds`/`absentRounds` 数据）。
- 任何新口径/规则必须先写入 `docs/RULES.md` 再实现。
